# ASC3ND Second-Wave Brand + Website Completion Plan

Status: planning only  
Production baseline: `50f6c0dfea63b9233e0d797408f368767de9ec10`  
Canonical public repo: `executiveusa/asc3nd-brand-site`

## Goal

Turn the current verified ASC3ND public site into a complete, bilingual, durable nonprofit brand experience that the founders can be proud to own and operate.

This is not a redesign for novelty. Preserve what already works:

- editorial restraint;
- founder-centered storytelling;
- documentary proof;
- accessibility;
- conservative truth handling;
- event evidence;
- mobile-first behavior;
- fast loading;
- clear calls to action.

The second wave adds a real brand system, a reusable event/gallery system, bilingual EN/ES delivery, a verified merch surface, and a detailed release standard.

## Design principle

**ASC3ND is the brand. Events are proof.**

No single event may visually become the identity of the nonprofit merely because it has more media.

Community Cuts should function as one proof object inside a growing longitudinal body of work.

## Visual world

### Emotional target

- credible
- hopeful
- grounded
- youthful without looking juvenile
- local/community-connected
- editorial/documentary
- dignified
- handmade enough to feel human
- polished enough to satisfy sponsors, families and funders

### Anti-references

Avoid:

- generic nonprofit stock-photo emotion;
- gradient-heavy AI branding;
- oversized event galleries on the homepage;
- startup SaaS visual language;
- excessive glassmorphism;
- 3D gallery theatrics;
- continuous marquee motion;
- autoplay decorative video;
- fake impact statistics;
- generated youth imagery presented as documentary truth.


## Extractor operating law

The second wave must run through The Extractor before visual redesign.

The Extractor is not an AI-authorship detector. It is a destruction-first reduction system.

Required sequence:

```text
R0 SOURCE
freeze current production
  ↓
DEFINE HUMAN JOB
  ↓
INVENTORY EVERY ELEMENT
  ↓
SLOP / EVIDENCE PASSES
  ↓
DELETE BEFORE REPLACING
  ↓
R1 ESSENTIAL
  ↓
R2 HUMAN
  ↓
R3 COMPOSED
  ↓
R4 MINIMUM USEFUL
  ↓
INDEPENDENT REVIEW
  ↓
VERIFY
```

### R0 protected baseline

Before changing design, record and preserve:

- production SHA and Vercel deployment;
- desktop and mobile screenshots;
- current navigation and routes;
- founder quotations;
- approved documentary photography;
- Community Cuts 86-photo archive;
- intake/form behavior;
- privacy, youth-safety and transparency copy;
- accessibility behavior;
- current event evidence state;
- current brand marks/wordmark behavior;
- rollback target.

### Human jobs by surface

#### Homepage

Visitor must understand:

1. what ASC3ND is;
2. who leads it;
3. why it is credible;
4. how it helps young people;
5. what real work it has done;
6. how the visitor can participate.

Primary action: choose a participation path.

#### Event archive

Visitor must understand:

1. what ASC3ND has actually done;
2. when and where;
3. what evidence exists;
4. what outcomes are verified versus pending.

Primary action: inspect a real event record.

#### Event record

Visitor must be able to:

1. understand the event;
2. view documentary evidence;
3. distinguish verified facts from pending claims;
4. see credits/partners when confirmed;
5. return to the broader ASC3ND story.

#### Merch

Visitor must understand:

1. what is actually for sale;
2. the actual price;
3. how fulfillment works;
4. what purchase does and does not mean financially;
5. how to buy or express interest.

#### Take-part flows

Visitor must understand:

1. which path applies to them;
2. what information is being requested;
3. what happens next;
4. what consent they are giving.

### Protected list

These elements may not be removed merely for minimalism:

- ASC3ND identity;
- founder names and approved quotations;
- documentary proof;
- meaningful uncertainty such as unverified outcome totals;
- youth-safety information;
- consent language;
- privacy language;
- accessibility;
- error recovery;
- event provenance;
- participation actions;
- client-approved legal identity;
- mobile usability.

### Extractor verdicts

Every meaningful existing or proposed element must receive one:

- KEEP VERBATIM
- KEEP AND REPOSITION
- REDUCE
- HUMANIZE
- REPLACE WITH EVIDENCE
- REMOVE
- MISSING AND REQUIRED

For every removal, record what would be lost.

### Eight required slop passes

Run:

1. Copy
2. Structure
3. Cognitive load
4. Trust
5. Visual UI
6. Motion
7. Code
8. Commercial clarity

### Specific ASC3ND applications

Examples:

- three-image homepage event gallery → **REDUCE** to one proof card;
- generic future-program filler → **REMOVE or REPLACE WITH EVIDENCE**;
- repeated ASC3ND slogans → keep only where they establish brand identity;
- decorative gallery motion → remove unless it explains spatial transition;
- generic card grids → reject unless they materially improve scanning;
- unverified merch copy/prices → **REPLACE WITH EVIDENCE**;
- repeated CTAs → consolidate around one next action per section;
- untranslated legal/form copy → **MISSING AND REQUIRED** for Spanish launch;
- generated imagery presented as real program proof → release failure.

### Release failure conditions

A second-wave release fails if it:

- removes required facts or meaningful uncertainty;
- invents proof;
- damages accessibility or form/error recovery;
- obscures the next action;
- flattens founder/brand voice;
- breaks mobile;
- reduces privacy/youth/legal requirements into slogans;
- claims production success without verification;
- introduces generic AI visual language that does not serve a human task.

No visual-polish score can average away one of these failures.

### Independent review

Builder cannot approve itself.

Required critics:

- Extractor reduction critic;
- humanization/copy critic;
- cognitive-load / Steve Krug pass;
- visual-detail pass using Details MCP;
- accessibility pass;
- mobile pass;
- commercial/trust pass.


## Phase 1 — Brand system

### 1.1 Preserve the approved concept

The current site concept uses:

- wordmark: `ASC3ND`
- crown mark
- warm paper background
- dark ink
- restrained gold/marker accent
- serif editorial display language
- documentary imagery

Do not throw this away.

The current wordmark is implemented as live text with optical correction to the numeral 3. It is not yet a proper portable master artwork.

### 1.2 Fal production workflow

Use Fal as a controlled production environment, not as the owner of brand truth.

#### Exploration

Primary exploratory route:

- `google/nano-banana-2.1/edit`
- use a rendered image of the current approved wordmark as reference;
- ask for restrained refinements, not replacement concepts;
- preserve exact spelling: **ASC3ND**;
- no invented tagline;
- no fake registration/trademark marks;
- no ornamental AI artifacts.

#### Vectorization / master candidates

Use:

- `ideogram/vector/text-to-vector`

It supports editable SVG output and reference images. Generate a small set of controlled vector candidates from the approved reference.

#### Human lock

The final master must be inspected and normalized before it becomes canonical:

- exact letterforms;
- exact 3 alignment;
- clean Bézier paths;
- no hidden raster content;
- no accidental text conversion artifacts;
- works at favicon size and large-format size;
- monochrome works without effects;
- passes black/white/reversed tests.

AI output is a candidate source, not automatically the master.

### 1.3 Required brand kit

Deliver:

#### Marks
- primary ASC3ND wordmark SVG
- black wordmark
- white/reversed wordmark
- single-color wordmark
- crown mark SVG
- compact/social mark
- horizontal lockup if approved
- favicon/app icon set
- PNG/WebP export set
- print-ready vector export

#### Rules
- clear space
- minimum size
- wrong-use examples
- background rules
- crown/wordmark relationship
- permitted color variants
- social-avatar treatment

#### Color
Start from current site palette, then validate contrast:

- paper
- ink
- field/dark
- marker/gold
- secondary neutral(s)

Do not expand into a large marketing palette unless necessary.

#### Typography

Run a small typography proof before locking.

Test three pairings against:
- ASC3ND wordmark;
- founder quote;
- English hero;
- Spanish hero;
- event metadata;
- buttons/forms;
- mobile 390px viewport.

Selection criteria:
- Spanish diacritics;
- readable body copy;
- strong editorial voice;
- useful weight range;
- stable rendering;
- reasonable web payload;
- no fashionable-but-fragile display choice.

The current Georgia/Arial pairing is a functional baseline, not automatically the final brand typography.

## Phase 2 — Homepage reduction

### Current problem

Even at three images, Community Cuts visually occupies too much homepage territory because the gallery itself becomes a major section.

### New homepage treatment

Replace the homepage gallery with one **Latest Work / Proof Card**.

Recommended composition:

```text
RECENT WORK · PROJECT 001

[ one strong documentary image ]

Community Cuts for Kids
Everett, Washington · August 2026

Short 1–2 sentence proof summary
[View event record →]
```

Optional desktop enhancement:
- one primary image;
- one small edge/detail crop only if it improves composition.

Mobile:
- one image only;
- no horizontal carousel;
- no hidden gesture dependency.

Community Cuts should occupy roughly one editorial section, not become a photo wall.

No event film on the homepage.

## Phase 3 — Reusable Events system

### Events index

`/events`

Each event card:

- sequence / year
- title

- location

- short verified summary

- status
- link to event record

Every event record can support:

No event-specific page architecture should need to be hand-built again.

## Phase 4 — Gallery

### 21st.dev research decision

Use 21st.dev as a component/reference source, not as a visual authority.

21st's current gallery guidance favors a simple grid for most production galleries, masonry only when mixed aspect ratios make cropping harmful, and a lightbox as the essential interaction.

For ASC3ND, mixed documentary portrait/landscape media makes masonry/shared-element behavior appropriate inside the event record, but not on the homepage.

### Preferred interaction reference

**Shared Element Gallery** is the strongest reference because it:

- preserves original image ratios;
- uses masonry;
- opens with spatial continuity;
- supports a premium documentary feel;
- can be adapted to touch interaction.

Use its interaction concept, not blindly its entire implementation.

Fallback:
- Masonry Lightbox.

### Keep from current ASC3ND gallery

The existing component already has important accessibility behavior:

- focus trap;
- Escape close;
- previous/next keyboard controls;
- focus return;
- swipe;
- approval/consent filtering.

Do not regress these features when adopting a 21st visual pattern.

### Performance contract

For an 86-photo event:

- first screen/row eager only;
- everything below lazy;
- responsive image variants;
- explicit image dimensions/aspect ratio;
- no downloading full-resolution originals for thumbnails;
- render first 12–18, then load more;
- do not decode 86 full-size images immediately;
- preserve image ordering;
- preserve consent/approval filtering;
- lightbox uses correctly sized image source;
- future pagination/virtualization ready.

### Mobile gallery

- two columns when useful;
- one column for particularly large/important documentary frames;
- original aspect ratios preserved;
- thumb tap target >=44px;
- swipe in lightbox;
- image counter;
- close within thumb reach;
- no hover-only meaning;
- no scroll hijacking.

## Phase 5 — Motion/detail system

Use Design Spells as an interaction reference library.

Motion should communicate state and spatial relationship.

Approved motion families:

- shared-element image open/close;
- soft fade/translate section reveal;
- tactile press states;
- subtle nav underline/opacity;
- language-toggle state transition;
- dialog/sheet transitions;
- merch image swap/selection state;
- small numeric/count transitions where meaningful.

Avoid:

- decorative perpetual motion;
- 3D spinning galleries;
- parallax that harms reading;
- scroll-jacking;
- long intro sequences;
- excessive cursor effects.

Respect `prefers-reduced-motion`.

## Phase 6 — Bilingual architecture

### URL structure

Use first-class locale routes:

- `/en`
- `/es`

and mirrored paths:

- `/en/events`
- `/es/eventos` or stable translated routing through an explicit route map;
- event slugs may remain canonical/stable for data ownership.

Do not use a browser-only machine-translation overlay.

### Required bilingual coverage

Translate and QA:

- homepage;
- founders;
- take-part pages;
- events index;
- event records;
- forms;
- validation/error/success messages;
- privacy;
- youth safety;
- transparency/giving;
- merch;
- metadata;
- alt text when language-relevant;
- email confirmations where applicable.

### SEO

Add:

- locale-aware metadata;
- canonical URLs;
- `hreflang`;
- locale-aware sitemap;
- language switch preserving equivalent page;
- `lang` attribute per locale.

Spanish must be human-reviewed before final publication. AI translation may draft, but is not the final QA authority.

## Phase 7 — Merch migration

The old site contains a prototype store with:

- Asc3nd Classic Logo Tee
- Elevate Youth Hoodie
- Asc3nd Collective Snapback
- Empowerment Tote Bag
- Future Leaders Mug
- Community Builder Poster
- Asc3nd Vinyl Sticker Pack

The old implementation uses placeholder imagery and hard-coded prices.

Therefore:

**Migrate the store concept, not the unverified commercial claims.**

Before publishing products:

- confirm actual products;
- confirm prices;
- confirm inventory/fulfillment model;
- confirm payment provider;
- confirm shipping geography;
- confirm refund/return policy;
- confirm whether purchase revenue is a charitable donation or ordinary merchandise sale;
- do not say purchases fund programs unless that claim is approved and supportable.

### New merch surface

`/[locale]/merch`

Initial safe states:

1. verified products can be purchased; or
2. curated "Merch coming soon" / interest collection if commerce is not ready.

Use the final brand kit to generate real product mockups only after products and print specs are confirmed.

## Phase 8 — Navigation / IA

Recommended primary navigation:

- About / Founders
- Work / Events
- Get involved
- Merch
- EN / ES

Keep the nav compact.

Do not add every nonprofit resource/profile to primary navigation.

Transparency/privacy/youth safety/contact remain footer or contextual links.

## Phase 9 — Details MCP + Codex build discipline

Add Details MCP to the development environment:

```bash
codex mcp add details --url https://api.details.so/mcp
```

Purpose:

- visual-detail review;
- spacing;
- responsive composition;
- typography;
- alignment;
- interaction states;
- micro-polish.

It is a review/build aid, not the source of organizational truth.

Codex build law:

1. read this plan;
2. inspect current component before replacement;
3. preserve accessibility behavior;
4. use 21st.dev only when component reuse beats custom code;
5. run Details review;
6. run mobile polish;
7. run Extractor;
8. build preview;
9. visually verify desktop + mobile;
10. merge only with rollback.


## Pre-build subtraction deliverable

Before Wave A implementation, produce a documented **ASC3ND R0 → R1 audit**.

The audit must show:

- baseline screenshot/reference;
- element;
- verdict;
- why;
- what is lost if removed;
- reversible action.

No redesign PR begins until this subtraction version exists.

The objective is not to make ASC3ND minimal. The objective is to remove what is generic, redundant, unsupported or distracting so that the real founders, work, mission and participation paths become more visible.

## Definition of done

The second-wave public site is complete when:

- ASC3ND has a real portable vector brand kit;
- site uses the locked brand tokens and typography;
- Community Cuts no longer visually dominates the homepage;
- every event can use the same data-driven gallery/template;
- Community Cuts still exposes all 86 approved images;
- English and Spanish are first-class site languages;
- merch exists in a truthful, production-appropriate state;
- forms and legal/safety copy work in both languages;
- mobile feels intentionally designed, not collapsed desktop;
- motion is purposeful and reduced-motion safe;
- all public claims remain evidence-backed;
- no new design removes existing accessibility behavior;
- every production change remains reversible.
