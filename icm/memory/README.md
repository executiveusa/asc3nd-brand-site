# M — Memory

Memory is the chronological operational record of the relationship.

## Canonical objects
- `asc3nd.person_memory` — durable relationship facts/events
- `asc3nd.touchpoints` — inbound/outbound/in-person interactions
- `asc3nd.followup_tasks` — what ASC3ND owes next
- `asc3nd.communication_consents` — purpose/channel permission ledger
- `asc3nd.content_drops` — approved communication units
- `asc3nd.content_deliveries` — person-specific delivery history

## Memory rules

1. Store observed events, not flattering summaries.
2. Keep source references.
3. AI-derived material is never silently promoted to fact.
4. Consent is appendable/revocable history, not a boolean marketing flag.
5. A sent message becomes a touchpoint/delivery; replies become new touchpoints.
6. Promises create follow-up tasks.
7. Do not delete history to simplify the dashboard; use lifecycle status and retention policy.

## First safe workflow

`Community Cuts RSVP → personal thank-you → selected-interest follow-up → explicit invitation to continue → ongoing content only after permission`

The agent may draft and prioritize. Human approval remains required for outbound personalized communication until a later explicitly approved automation policy exists.
